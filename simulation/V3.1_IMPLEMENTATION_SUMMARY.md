## 🎓 Key Learnings

### Design Decisions
1. **Why 3-phase link placement?**
   - Source link enables harvester efficiency
   - Spawn link enables distribution
   - Second source doubles throughput
   - Controller link deferred to RCL 7+ (lower priority)

2. **Why throttle LinkManager to every 3 ticks?**
   - Link cooldown is ~8-10 ticks (distance-based)
   - Checking every tick wastes 5-7 ticks of CPU
   - Every 3 ticks is optimal balance

3. **Why increase haulers during transition?**
   - Link construction takes 30-60 minutes
   - Energy demand increases (30 extensions)
   - 3 haulers prevent starvation during build
   - Auto-reduces once links operational

### Code Patterns Applied
- **Chess engine philosophy**: Position evaluation → Move generation → Execution
- **Priority system**: Critical structures first (links > containers > roads)
- **Throttling**: All expensive ops run on intervals (structure planning: 100, links: 3, towers: 1)
- **State machines**: Creeps toggle between states (working/collecting)
- **Caching**: Structure finds cached to reduce CPU

## 📞 Troubleshooting

### "Links not appearing?"
- Wait for structure planner cycle (every 100 ticks)
- Check console for 🔗 messages
- Verify RCL 5: `Game.rooms.W13N57.controller.level`

### "Energy still low?"
- Haulers should auto-scale to 3 at RCL 5
- Check: `_.filter(Game.creeps, c => c.memory.role === 'hauler').length`
- Wait for extensions to finish building (5 under construction)

### "Link not transferring?"
- Check link cooldown: `link.cooldown` (should be 0)
- Verify energy in source link: `link.store[RESOURCE_ENERGY]` (needs 400+)
- Check target link capacity: Should have room for 800 energy

### "CPU increased?"
- Links initially add ~0.5 CPU (link manager + harvester checks)
- Once haulers reduce to 1, net CPU should drop 20-30%
- Full benefit realized after link construction complete
